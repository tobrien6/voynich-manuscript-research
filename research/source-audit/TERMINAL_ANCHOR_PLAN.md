# Terminal native-locus review plan

## Target and purpose

Select the sole present `f116v.1,@Lx` record in the pinned terminal intake.
Selection uses source coverage, with no agreement or readability filter. Retain
ZL3b and both RF contexts; retain the absence of an `f116v` header in IT2a and
GC2a. Three related file versions are not three independent image witnesses.

Define source-linked native-pixel review windows for the possible image
association. This supplies a concrete region for independent checking, not a
verified glyph reading or a corpus alignment. The publisher's description
places the native pair at the beginning of the lowest of the four upper rows;
that position is a reported claim to test against the image.

## Fixed procedure

1. Reuse the intake's exact Yale `116v` canvas, image service and dimensions.
   Preserve the original full-image and upper-writing-region fingerprints.
2. Inspect a window containing the beginning of the lowest upper row, enough
   neighboring writing to place it in context, and a narrower native-pixel
   window around the possible pair. Coordinates may be chosen from the already
   exposed upper-writing image; record them before fetching each derivative.
3. Record official URLs, native coordinates, image bytes' SHA-256 digests and
   decoded dimensions. Keep image pixels local. Do not call review windows
   exact glyph or token boxes.
4. Preserve each present source's alphabet, pin, physical file line,
   identifier, subtype, locator, native payload outside free comments and
   comment-presence flag. Do not convert inline comment text to native script.
5. Report observations and the association basis separately. Retain an
   unresolved outcome if the pair cannot be located confidently. Do not change
   the source, interpret the adjoining writing, supply a language or translation,
   infer handwriting identity, or resolve the historical folio alias.
6. Metadata checks must reject missing/altered source contexts, invented
   missing-edition records, unsupported confirmed/verified claims, and absent
   or inconsistent review-window metadata. They cannot certify visual evidence.

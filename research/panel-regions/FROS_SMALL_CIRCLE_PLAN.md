# Rosette small-circle region review plan

Question: can the source's small circular feature and its surrounding layout
locate four native rosette loci provisionally on the Yale carrier?

Targets are fixed before this contribution retrieves or inspects the image:
`fRos.112,@L0`, `fRos.113,=Cc`, `fRos.114,+Ca`, and `fRos.115,=L0` in pinned
ZL3b and GC2a. These are the contiguous source-defined group with ZL comments
for left, above, below, and right of the author's named circular feature.
Do not choose targets after seeing which glyph strings are easiest to match.

The source author's term "clock" is a locator description, not a validated
interpretation of the drawing. IVTFF issue 2.0.2, Table 9 on printed page 22,
defines Cc and Ca as clockwise and anticlockwise circular text respectively.
Table 8 on page 21 defines the relative locator symbols. These annotations are
predictions to check against layout, not independent observations.

Inputs: accepted ZL3b/GC2a catalog bytes and the existing IVTFF reader; original
pilot image 1006231, labeled `85v and 86r (foldout)`; pinned canvas index and
manifest audit. Retain the source hashes, complete native text/annotations,
source physical line numbers, reader pins, exact canvas, both named sides,
and the `yale-leaves:85+86` dependency. Check all four present locus identifiers
and kinds in both editions; missing or substituted targets fail the checklist.

Image procedure: first view a whole-surface bounded derivative, then inspect
the candidate circular region at a larger source resolution if necessary.
Record the actual derivative URL, bytes, dimensions, SHA-256 and inspection
order. Record a broad normalized rectangle only if the candidate is clearly
located. A rectangle identifies an inspection region, not exact text masks,
folio/panel boundaries, or a verified glyph alignment. Do not make equal-width
panel crops or derive physical leaf identity from image x coordinates.

Decision rule: record compatible, incompatible or unresolved layout separately
for the four source annotations. The pattern must include both short arcs and
the two flanking labels; do not choose a circle based solely on its appearance.
If this whole pattern cannot be located, leave pixel regions null and report
the failed association. Preserve image/text uncertainty and any disagreement.
Do not infer readings, word boundaries, circular direction or start positions
from unreadable glyphs. A clock-position comment is source metadata, not a
validated start point on the image.

Scope: this is a targeted, informed AI-assisted layout check, not a blind test
or independent expert review. The existing pilot already inspected this image;
the accepted convention notes and native ZL/GC text/comments were read before
this plan. No untouched evaluation material is created. Keep the region proposal
unverified and excluded from statistical corpus joins and pilot completeness.

Next test: independent reviewers should check the original-resolution glyphs,
the proposed arc directions/start positions and the four full native readings,
including alternative glyphs, ligatures and uncertain spaces. Any verified
locus-to-image crosswalk is a separate reviewed contribution. This plan does
not register a decipherment or translation hypothesis.

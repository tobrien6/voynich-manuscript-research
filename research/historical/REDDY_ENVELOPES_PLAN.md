# Native H / paper-associated Reddy envelope plan, version 1

Question: do the literal record identifiers, order and token counts in the
recovered Reddy full annotated file correspond to the 1.6e6 native H release,
despite their known 5,213/5,214 record totals and equal 37,919 token totals?

Publish this plan and synthetic-tested producer before computing the cross-source
join. Both parent inventories, historical parsing counts, full source material
and the two leading annotated header formats are already exposed. This is a
descriptive input-identity audit, not untouched evaluation, a glyph map, verified
physical alignment or proof of original-author 2011/2013 bytes.

## Pinned sources and complete parent replay

Reuse the exact publisher-hosted 1.6e6 archive/member and selected native `H`
records. Reuse all six locally retained Reddy manifest files at commit
`643b881b2937bae8193814d8ff5d6e99a48bf7c5`, without executing author code or
redistributing corpus bodies. Verify each file's byte count, SHA-256 and Git
blob identity. Require complete accepted Reddy intake, native H intake and
historical parsing report replay before the new comparison. Pin their catalogs,
source/reader/helper/plan/report bytes in the machine parameters.

Reddy's full annotated file uses four whitespace-separated fields inside `<...>`.
Join their literal tuple to `(native page, native unit, native line, transcriber)`.
Preserve case, suffixes, units, source tags and exact strings. No label alias,
panel collapse, guessed page pairing, lowercase projection, token spelling match
or optimized alignment is introduced. Duplicate keys fail; each source's original
order and physical file-line references remain separately recorded.

## Two fixed historical count stages

For every H record, reuse accepted comment/filler/separator normalization with
an empty special-code set: coded fallback characters remain. Also report the
accepted listed-code deletion interpretation before manual exclusions. Compare
both counts to Reddy's unchanged whitespace token count, without comparing the
unverified notations as identical glyphs or words. Do not apply the four manual
ring/f66r/label exclusion variants, trim records to match totals or tune a rule.

Retain every key in the union and distinguish H-only, Reddy-only and shared
keys. For each record, publish native descriptors/ordinals/file lines, body or
token-vector hashes, both H normalized counts, Reddy token count and each signed
count difference/equality flag. Publish no raw token strings, bodies or author
program payload. Include empty H normalizations and all one-sided cases.

## Complete accounting and order

Report original and shared record totals, empty/nonempty counts, full token
totals under all three streams, shared/unmatched contributions and all signed
positive/negative count sums. Global equal counts must not hide cancellation.
Retain every union-page summary with original record and token denominators.

Compare the shared-key sequences in their respective original source orders.
Retain ordered-key digests, an exact order equality flag and every discordant
shared rank if unequal. Do not sort before claiming preserved order. Full record
descriptors supply original H/annotated source ranks even when their key join is
unambiguous. These are nominal source identifier correspondences; physical/image
identity, alphabet conversion and a historically used transformation remain
separate questions.

## Validation, reuse and limits

Before source computation, test direct shared keys, one-sided/empty records,
order changes, nonzero signed cancellation despite equal totals, suffix/unit/case
distinctions, duplicates and malformed headers, both normalizations, strict
parent/source/dependency mismatch and output failure preservation. Protect all
local references, frozen files, plans/readers/producers against direct/symlink/
hardlink aliases before calculation and immediately before writing, including
aliases introduced during computation. Keep both parent reports unchanged.

Retain all results, including disagreement or no gap resolution. Native H reuse
credits/terms and the Reddy repository's absent-license/raw-local-only limitation
must remain explicit. No raw corpus, author source, image or PDF is added to the
outgoing contribution. Matching identifiers/counts/order does not prove equal
text, equivalent alphabets, verified glyphs, source correctness, a historical
execution, a language, decipherment or translation. The separate H/IT2a projected
record-order work uses different sources and a different lossy comparison.

# Additional runtime replay and initialization accounting

Two fresh Zulu OpenJDK 17.0.16 processes built from the pinned source produced
the supplied release artifact byte for byte. Their SHA-256 also matches both
release-case outputs recorded on Homebrew OpenJDK 22.0.2 in
[PR #88](https://github.com/tobrien6/voynich-manuscript-research/pull/88).
This adds an observed runtime/build comparison and a complete row ledger.
It is not a general portability proof or a manuscript mechanism evaluation.

## Recorded scope

The [Java 17 plan](SELF_CITATION_JAVA17_PLAN.md) was committed before execution
at `af4ae40c5261ecfb6f14b7eeb1c511299604a804`, under filename
`SELF_CITATION_REPLAY_PLAN.md`. The current filename preserves exactly those
bytes and distinguishes this plan from the parallel contribution's plan.
Source and supplied output had already been exposed. The
[record](self-citation-java17-replay.json) retains both plan paths and its hash.
The row-audit helper was created after execution for the planned identity/count
diagnostics, not frozen as a manuscript prediction or fitting rule.

All 35 Java files at author commit
[`9e98c9122a0f490905e8b66f3911fc7ce095fd26`](https://github.com/TorstenTimm/SelfCitationTextgenerator/tree/9e98c9122a0f490905e8b66f3911fc7ce095fd26)
were compiled unchanged with `javac 17.0.16 --release 8 -encoding UTF-8` and a
256 MiB compiler heap. The 39-file intake includes their exact Git blob/SHA-256
identities, the POM, resource configuration, executable configuration and
supplied text. All 21 overlapping earlier audit pins match. The build yielded
47 class files, each fingerprinted, with no external dependency JAR. Neither
Maven packaging nor the packaged generator JAR was executed.

Each JVM ran in its own new directory with the unchanged complete executable
configuration, seed 19 and 1,200 requested rows. The record retains its hash,
runtime/platform, heap limit, UTF-8 encoding, locale/timezone, minimal environment
and all process/log/output identities. Both exited zero without timeout under
the 60-second process cap. Date-dependent filenames are retained as metadata;
their contents were compared without normalization or header removal.

## Input, output row and group occurrences are different counts

The [CSV ledger](self-citation-java17-rows.csv) has one record per data row,
retaining physical file line, ordinal, input/generated origin, notation-character
count, literal-space group count and row hash. It publishes no row strings.

| Counted object | Result |
| --- | ---: |
| Physical file lines | 1,235 |
| Comment lines | 35 |
| Blank physical lines | 0 |
| Data rows including initialization | 1,200 |
| Newly generated rows | 1,199 |
| Group occurrences including the stored initialization row | 10,832 |
| Newly generated group occurrences | 10,823 |
| Configured initialization: notation characters / group occurrences | 67 / 11 |
| Stored initialization row: notation characters / group occurrences | 59 / 9 |

The first data row is physical file line 36. The source's
[`initStatistics()` and `trimInitialLine()`](https://github.com/TorstenTimm/SelfCitationTextgenerator/blob/9e98c9122a0f490905e8b66f3911fc7ce095fd26/source/src/main/java/de/voynich/text/SelfCitationTextGenerator.java#L55)
present the input groups to statistics before trimming the line stored in output.
Thus the configured and stored initial strings have different hashes and counts.
Removing the first written row from a later statistic does not remove the full
input line's influence on generation. This remains manuscript-derived exposure,
not successful prediction of the nine stored groups or unseen text.

The newly generated row lengths range from 13 to 56 ASCII notation characters.
Those observations are distinct from configured values 15 and 55; the program's
layout, substitutions and space insertion determine its actual strings. No
physical glyph-width measurement or manuscript writing-row count is inferred.
Space-delimited groups are also distinct from the algorithm's internal segments.

## Check the row bridge offline

For an existing local output and its complete configuration, use **new** record
and ledger paths:

```sh
python3 scripts/audit_self_citation_rows.py PATH_TO_LOCAL_GENERATED_FILE \
  --configuration PATH_TO_COMPLETE_CONFIGURATION \
  --new-record PATH_TO_NEW_ROW_RECORD.json \
  --new-ledger PATH_TO_NEW_ROW_LEDGER.csv
PYTHONPATH=tests python3 -m unittest test_self_citation_rows
```

The helper downloads and executes nothing. It preserves physical lines, literal
space boundaries and complete byte fingerprints. Non-ASCII/unsupported notation,
empty space-delimited slots, mixed line endings and missing data rows fail rather
than being silently normalized. Existing files or symlinks and duplicate output
paths are rejected. LF and CRLF may yield equal row metadata while retaining
different whole-file hashes. Tests use synthetic examples plus independent sums
and ordinal checks of the committed 1,200-row ledger; they do not certify process
history, manuscript alignment or mechanism adequacy.

All source/class/configuration/log/output pins and the ledger were checked
against the retained local files. Third-party source, binaries, full configuration,
logs and generated text remain local. Only original metadata, counts, fingerprints
and analysis are submitted. The [static implementation audit](COPYING_MECHANISM.md)
and its [comparison requirements](COPYING_MECHANISM.md#a-later-experiment-must-freeze-these-choices)
remain the starting point for a separately frozen mechanism experiment.
